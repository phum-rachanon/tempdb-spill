# EP4 – ขนาดคอลัมน์และ data type ทำให้ grant เพี้ยน

ความยาว 10–12 นาที · Database: StackOverflow2013 · พื้นฐานที่ควรมี: [EP1](../ep01-memory-grant/)–[EP3](../ep03-hash-spill/)

## EP นี้ผู้เรียนได้อะไร

- รู้ว่า SQL Server ประมาณขนาดแถว (Estimated Row Size) จากชนิดและขนาดที่ประกาศ ไม่ใช่จากข้อมูลจริง
- เห็นว่าคอลัมน์ที่ประกาศใหญ่เกินจริง และ nvarchar(max) ทำให้ grant บวม
- เห็นว่าข้อมูลที่ยาวเกือบเต็มขนาดที่ประกาศทำให้ grant ต่ำไปจน spill ได้
- รู้วิธีเขียน query ให้ Sort แบกคอลัมน์กว้างน้อยลง

## EP นี้แก้ปัญหาอะไร

| ปัญหาที่เจอ | EP นี้ช่วยยังไง |
|---|---|
| statistics ถูกต้องแล้ว แต่ query ยัง spill | ชี้ว่าข้อมูลที่ยาวเกือบเต็มขนาดที่ประกาศทำให้ประมาณขนาดแถวต่ำไป |
| query ที่มีคอลัมน์ข้อความยาวจอง memory มหาศาล | แสดงว่า nvarchar(max) และคอลัมน์ที่ประกาศใหญ่เกินทำให้ grant บวม |
| SELECT * ในหน้ารายการหรือรายงานทำให้ช้าและกิน memory | เลือกเฉพาะคอลัมน์ที่ใช้ และเรียง key ก่อนแล้วค่อยดึงคอลัมน์กว้าง |
| ออกแบบตารางใหม่ ไม่แน่ใจว่าควรประกาศขนาดคอลัมน์เท่าไหร่ | เข้าใจผลของขนาดที่ประกาศต่อ grant เพื่อเลือกขนาดให้สมจริง |

## เนื้อหาพร้อมตัวอย่าง

### 1. ขนาดแถวถูกประมาณยังไง

| ชนิดคอลัมน์ | ขนาดที่ใช้ประมาณ |
|---|---|
| ขนาดคงที่ (int, bigint, datetime, char(n)) | ขนาดจริง รู้แน่นอน |
| varchar(n) / nvarchar(n) | ราวครึ่งหนึ่งของขนาดที่ประกาศ |
| varchar(max) / nvarchar(max) | ค่าคงที่ขนาดใหญ่ (ราวหลักพันไบต์ต่อค่า) ไม่ว่าข้อมูลจริงจะสั้นแค่ไหน |

- ดูได้ที่ **Estimated Row Size** ใน tooltip ของ operator
- optimizer ไม่มี statistics เรื่องความยาวข้อความในคอลัมน์ จึงต้องเดาจากขนาดที่ประกาศ
- ตัวเลขที่แน่นอนขึ้นกับรุ่น SQL Server ให้ดูจาก Estimated Row Size บนเครื่องตัวเอง

ผลที่ตามมา (เพราะ grant ≈ จำนวนแถว × ขนาดแถว):

| สถานการณ์ | ผล |
|---|---|
| ประกาศใหญ่กว่าข้อมูลจริงมาก หรือใช้ (max) | grant บวม เปลือง memory (Excessive Grant) |
| ข้อมูลจริงยาวเกือบเต็มขนาดที่ประกาศ | grant ต่ำกว่าที่ต้องใช้จริง เสี่ยง spill แม้จำนวนแถวประมาณถูก |

สิ่งที่สำคัญ: กรณีหลังคือ spill ที่เกิดทั้งที่ statistics ถูกต้อง 100% อัปเดต statistics กี่รอบก็ไม่หาย

### 2. ตัวอย่าง: เพิ่มคอลัมน์ nvarchar(max) เข้า SELECT

ไฟล์: [`sql/01-nvarchar-max-in-select.sql`](sql/01-nvarchar-max-in-select.sql)

เทียบสอง query:

- Estimated Row Size ที่ Sort: query ที่สองใหญ่กว่าหลายเท่า
- DesiredMemory / GrantedMemory: query ที่สองขอมากกว่า อาจชนเพดาน MaxQueryMemory
- MaxUsedMemory: ใช้จริงน้อยกว่าที่ได้มาก เพราะ AboutMe ส่วนใหญ่ว่างหรือสั้น

### 3. ตัวอย่าง: ข้อมูลเดียวกัน ประกาศขนาดต่างกัน

ไฟล์: [`sql/02-declared-size-compare.sql`](sql/02-declared-size-compare.sql)

- ข้อมูลทุกแถวเหมือนกัน ต่างกันแค่ขนาดที่ประกาศ (nvarchar(40) กับ nvarchar(4000))
- NameBig ได้ Estimated Row Size ใหญ่กว่ามาก grant บวม และอาจเห็นคำเตือน Excessive Grant ที่ SELECT
- บทเรียน: อย่าประกาศ nvarchar(4000) หรือ (max) เผื่อไว้ก่อน ถ้าข้อมูลจริงยาวไม่กี่สิบตัวอักษร

### 4. ตัวอย่าง: ข้อมูลยาวเกือบเต็มขนาดที่ประกาศ → spill

ไฟล์: [`sql/03-full-length-data-spill.sql`](sql/03-full-length-data-spill.sql)

- จำนวนแถวประมาณถูกเป๊ะ แต่ขนาดแถวถูกประมาณไว้ราวครึ่งเดียวของความจริง
- ผลที่ควรเห็น: MaxUsedMemory เต็ม Granted และ Sort มีคำเตือน spill (ขึ้นกับส่วนเผื่อของ grant บนแต่ละเครื่อง ถ้าไม่ spill ให้เพิ่มคอลัมน์แบบเดียวกันอีกสองสามคอลัมน์)
- อัปเดต statistics แก้ไม่ได้ เพราะต้นเหตุอยู่ที่ขนาดแถว ไม่ใช่จำนวนแถว

### 5. วิธีลดคอลัมน์กว้างที่ Sort ต้องแบก

ไฟล์: [`sql/04-sort-keys-then-fetch.sql`](sql/04-sort-keys-then-fetch.sql)

- **เลือกเฉพาะคอลัมน์ที่ใช้จริง** หลีกเลี่ยง SELECT * ใน query ที่มี ORDER BY, GROUP BY หรือ JOIN ใหญ่ๆ
- **เรียงเฉพาะ key ก่อน แล้วค่อยดึงคอลัมน์กว้าง** เหมาะกับการแสดงผลทีละหน้า หรือ TOP N
- **ประกาศขนาดคอลัมน์ให้สมจริง** ตอนออกแบบตาราง รวมถึง temp table และ table variable ที่เราสร้างเอง

ข้อควรระวัง: การ CAST คอลัมน์ให้เล็กลงใน query เพื่อหลอก optimizer เปลี่ยนค่าประมาณได้จริง แต่ตัดข้อมูลที่ยาวเกินทิ้งทันที ใช้เฉพาะตอนรู้แน่ว่าข้อมูลไม่เกินขนาดนั้น

ล้างตาราง demo: [`sql/05-cleanup.sql`](sql/05-cleanup.sql)

## สรุปตอนท้าย

- grant ขึ้นกับขนาดแถวพอๆ กับจำนวนแถว และขนาดแถวคิดจากขนาดที่ประกาศ ไม่ใช่ข้อมูลจริง
- varchar/nvarchar(n) ถูกประมาณราวครึ่งของขนาดที่ประกาศ, (max) ถูกประมาณใหญ่เสมอ
- ประกาศใหญ่เกิน → grant บวม / ข้อมูลยาวเกือบเต็ม → grant ต่ำไป เสี่ยง spill แม้ statistics ถูกต้อง
- เลือกคอลัมน์เท่าที่ใช้ เรียง key ก่อนแล้วดึงคอลัมน์กว้าง และประกาศขนาดให้สมจริง
